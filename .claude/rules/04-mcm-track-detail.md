# MCM Track — 流程细节（按需加载）

> 本文件是 `.claude/rules/04-mcm-track.md` 薄壳的**参考层**：承载流程细节、环节清单、Agent 分工与强制规则详解。
> **凡涉及具体环节执行，以本文件为准**。路由与硬约束在薄壳中，两者不重复。
>
> ⚠️ 本文件由 `paths:` 触发（读 `agents/mcm/**`、`knowledge/mcm/**`、`outputs/mcm_*/**` 时加载）。
> 若某会话从未读这些路径，本文件不进上下文——**此时薄壳中的硬约束仍然生效**，这是刻意的安全降级设计。

## 协作模式：总规划 → 环节循环 → 终稿合并

```
选择 MCM 赛道
│
├─ 【总规划 · 一次性】
│   ├─ P0 topic-agent  选题评估（题目已定可跳过，N0）
│   ├─ P1 planner-agent 审题拆解 + 全局 A/B 模型方案 + 关键小问 + 【环节清单】+ 论文骨架（N1/N2）
│   └─ P2 data-agent   数据审查与预处理（与 P1 并行，N3）
│
├─ 【环节循环 · 逐环节：plan → auto → 完成+自检 → 停止】★执行建模在前（依赖驱动），每节写作按 skill 模板
│   ├─ 环节① 问题重述               (writer)
│   ├─ 环节②~⑥ 问题一~五：建模与求解 (model-builder → coder → diagnosis → writer，含嵌入分析段+稳健性+结论)
│   ├─ …   逐问展开（按小问数量增减，依问题耦合顺序）
│   ├─ 环节⑦ 模型假设               (writer，各问模型已建后写，"每条假设进模型"自然可溯)
│   ├─ 环节⑧ 符号说明               (writer，从已写模型节提取符号表)
│   ├─ 环节⑨ 模型评价               (writer，依赖全部结果，只写优缺点)
│   ├─ 环节⑩ 参考文献               (writer，仅列正文实际引用)
│   ├─ 环节⑪ 附录                   (脚本拼源码 + writer 只写指针与关键片段)
│   └─ 环节⑫ 摘要                   (writer，最后合成，强制反 AI 自检)
│
└─ 【终稿合并 · 一次性】
    ├─ 合并 paper/sections/*.md → 论文草稿.md
    ├─ writer 补答案速查表（每问一行，随环节已逐步累积）
    ├─ critic-agent 评审自查表（N7 唯一触发）
    ├─ 团队按 N7 清单核验 → 交付（论文 + 代码 + 答案速查表）
    └─ （可选）math-modeling-writing 内置 md2word 转 Word + 无损校验
```

### 每环节工作流（plan → auto → 完成+自检 → 停止）

1. **plan**：主控读取 `part_scope`（目标章节/小问），结合环节清单声明该环节所需输入与依赖的已产出；对含建模的环节，planner/model-builder 先给该问的细化方案。
2. **auto**：按环节调用对应 agent——建模环节为 model-builder（该问推导）→ coder（该问 `problemN.py`，物理运行）→ diagnosis（该问检验+灵敏度）；纯写作环节直接 writer。
3. **完成**：writer 加载 skill 对应章节模块（`references/sections/*.md`）写出**一节一个文件** `paper/sections/{序号}-{章节}.md`，编号衔接已有草稿；执行该模块**自检清单**（强制最后一步）；含代码的环节过物理验证。
4. **停止**：主控将该环节产出（sections 文件 + 结果 + 自检结果）写入状态记录，**汇报后暂停，等待用户发出下一环节指令；不擅自连跑后续环节**。
   - **真决策点**（N0 选题 / N2 模型路线 / N7 终稿）是**需要团队实质裁决**的停点，与逐环节的常规停点相区分——常规停点用户回一句"继续"即可。
   - **例外**：用户显式说"连跑后面 N 个环节"时，按指令批量执行，执行完仍回到停点。
   - 用户随时可插话指定环节（"做问题三的建模与求解" / "写模型假设" / "出全文"，part_scope 优先生效）。

### 环节清单（执行建模在前、依赖驱动；每节写作按 skill 模板模块）

> **本表是全流程环节清单的唯一出处**。`agents/mcm/agent.md`、`agents/secretary.md`、
> `knowledge/mcm/templates/paper-structure.md` 只引用本表，不另列一份。

| 环节 | 章节模块 | 输入依赖 | 对应 agent | 人工角色 |
|------|---------|---------|-----------|---------|
| ① 问题重述 | `restatement.md` | 仅题目 | writer | 写作手 |
| ②~⑥ 问题N 建模与求解（逐问） | `model-solve.md`（含 analysis 嵌入、稳健性、结论） | 题目+数据+全局方案+上游问结果 | model-builder→coder→diagnosis→writer | 建模手→编程手→写作手 |
| ⑦ 模型假设 | `assumptions.md` | 题目 + 各问已建模型（每条假设可追溯进模型） | writer | 写作手 |
| ⑧ 符号说明 | `notation.md` | 各问已写模型节的模型表达式（提取符号表） | writer | 写作手 |
| ⑨ 模型评价 | `evaluation.md` | 全部建模+结果（只写优缺点） | writer | 写作手 |
| ⑩ 参考文献 | `references.md` | 正文实际引用 | writer | 写作手 |
| ⑪ 附录 | `appendix.md` | 代码+运行结果 | `scripts/build_appendix.py` 拼源码 + writer 写指针 | 写作手 |
| ⑫ 摘要（最后） | `abstract.md` | 题目+各问模型概述+核心数值 | writer（强制反 AI 自检） | 写作手 |

**前置与终末的一次性 Agent（不占环节序号）**

| 阶段 | Agent | 调用时机 | 关键产出 |
|------|-------|---------|---------|
| P0 选题评估 | `topic-agent` | 一次性（题目已定可跳过） | 选题评估表 + 推荐决策 |
| P1 审题拆解 + 全局模型方案 | `planner-agent` | 一次性（与 P2 并行） | 拆解表 + 模型方案 + 关键小问 + **环节清单** + 论文骨架 |
| P2 数据审查与预处理 | `data-agent` | 一次性（与 P1 并行） | 数据字典 + 质量检查 + 清洗规则 |
| — 终稿审查 | `critic-agent` | 终末（N7 唯一触发） | 评审自查表逐项 PASS/FAIL |

> 建模在前使模型假设、符号说明从**已建成的模型**中提取，内容最准（"每条假设进模型"、符号与最终表达式一致自然满足）；每节写作仍严格按 skill 模板模块（输出骨架/写作规则/自检清单），论文排版顺序按 skill 结构（模型假设、符号说明置于建模求解之前）。环节顺序可由用户灵活调整（"先做问题三"也可），但默认按上表依赖驱动。

## 强制规则

### 1. 评审导向（核心原则）
- 每个环节的产出必须对齐评委最终能看到的东西
- 摘要必须包含与题型匹配的可检验关键结果（非"取得较好效果"等空泛表述）
- 每个小问的答案可在 30 秒内定位

### 2. 答案要求
- 优化题：最优方案 + 目标值
- 预测题：预测值 + 误差区间
- 评价题：排序/分级 + 权重
- 机理题：解析表达 / 规律 / 阈值
- 多目标/情景题：折中方案 / Pareto 解 / 区间

### 3. 模型纪律
- 优先选择可解释、可运行、可检验且与团队能力匹配的模型
- **禁止模型堆砌**：新增模型必须说明解决了基础模型的何种具体困难
- **禁止伪造创新**：不得将常规模型、预处理或常规可视化表述为创新
- 每模型必须说明：输入输出、关键假设、适用条件、局限、基准方案、检验方法
- 设置至少一个基础基准模型

### 4. 数据纪律
- 以实际附件为唯一依据，不得编造字段、样本或数值
- 必须检测数据泄漏（train/test 偏移、目标泄漏、时间泄漏）
- 外部数据仅在题目允许且确有必要时使用
- 所有外部数据必须说明来源、获取日期和处理方法

### 5. 代码纪律
- 代码须模块化（data_loader, preprocessing, models, visualization, utils 分离）
- 必须包含：字段校验、随机种子、集中式配置、异常提示、结果导出
- 未运行结果一律标记 `[待运行]`
- 固定随机种子确保可复现
- **逐问实现**：每个环节只实现该问 `problemN.py` 及直接依赖；`main.py` 支持逐问独立运行

### 6. 论文纪律
- **篇幅（官方硬约束）**：正文从第四页开始，**不超过 30 页**，且**不要目录**；正文之后是论文附录，**页数不限**。
  30 页只约束正文：附录在正文之后，第四条明文「页数不限」；摘要专用页（论文第三页，含标题与关键词**原则上**不超过一页）在正文之前，不计入该额度
  —— 末句系据第四条推导（30 页的限定语仅附着于「正文内容」），**非规范原文**。
  依据《全国大学生数学建模竞赛论文格式规范》(2026) 第三条、第四条，原文见 `knowledge/mcm/templates/format2026.txt`。终稿合并（N7）须核对正文页数
- **逐问预算（默认口径）**：逐问节每问约 6 页，写作类固定节（重述/假设/符号/评价/参考文献）合计约 6 页，正文 ≤30 页。
  页数只作**粗控**——每环节产出后主控扫一次字数，明显超支（该问 >8 页）再处理；不做精确页数核算，不因 0.5 页的偏差退回重写。
  纯验证性证据（样本外检验、退化极限、唯一性证书、明细图）可放附录，附录页数不限，正文保留结论句 + 指针
- 使用正式中文；流程图使用 Mermaid；符号首次出现必须定义
- **禁止 AI 套话**：遵守 `.claude/rules/02-academic-writing-standards.md` 禁用词表
- 每个结论必须有真实数据、公式、表格或图形支撑
- 参考文献须逐条核验，按 GB/T 7714 格式
- **写作强制引用 `math-modeling-writing` skill**：每节写作必须加载对应 `references/sections/*.md` 模块，按该模块"输出骨架/写作规则/常见句式"撰写，执行该模块**自检清单**为最后一步；摘要强制以"反 AI 自检"为最后一步，未通过则重写
- 产出文件约定：每节一个独立文件 `paper/sections/{序号}-{章节}.md`，编号衔接已有草稿；整篇模式在终稿合并时逐节合并

## 环节自检与关键节点（逐环节停止；真决策点团队把关）

**前置一次性节点**（N0~N3）与**环节自检**（S）与**终稿节点**（N7）三段式，检查清单见 `knowledge/mcm/templates/node-checklists.md`：

| 节点 | 覆盖环节 | 判定时机 |
|------|---------|---------|
| N0 选题评估 | 总规划 P0 | 一次性（团队确认题目） |
| N1 审题拆解 | 总规划 P1 | 一次性（主控自检 + 团队可审） |
| N2 模型方案 | 总规划 P1（含环节清单） | **真决策点**：暂停请团队确认模型路线 |
| N3 数据审查 | 总规划 P2 | 一次性（主控自检 + 团队可审） |
| S 环节自检 | 每个环节完成后 | AI 自检记录 + 汇报，随后**暂停等指令** |
| N7 论文终稿 | 终稿合并 | **真决策点**：暂停请团队按清单核验 |

每个节点的检查规则：
- **判定者**：真决策点（N0/N2/N7）由团队确认；其余节点由主控按清单自检并记录，用户在**每个环节停点**自然审阅该环节记录
- **通过**：清单全部核验通过 → 记录 PASS → 进入下一环节/节点
- **不通过**：记录 FAIL + 退回对象 → 退回对应 Agent 修复后重新核验
- **S 环节自检**：该节自检清单逐项 + 数值真实与运行结果核对 + 编号/图表衔接 + 含代码时物理验证，结果写入状态记录；critic 仅终稿（N7）执行评审自查表
- **状态记录**于 `outputs/mcm_{题目}/checkpoints/节点状态记录.md`（含节点/环节/产出/核验/确认/状态/时间/退回对象）。**列结构（表头）以 `knowledge/mcm/templates/node-checklists.md` §节点/环节状态记录模板 为唯一出处**，本文件不复述列名

节点检查的通用底限：
- 当前环节关键问题已回答
- 团队已审核无明显事实/逻辑/公式/单位错误
- 未运行内容已标注 `[待运行]`
- 当前方案符合时间预算

## 与学术流水线的差异

| 维度 | 学术流水线 | MCM 赛道 |
|------|-----------|---------|
| 目标 | 方法论创新 | **评审得分最大化** |
| 模型可解释性 | 必须 | 必须（评委可读） |
| 特征工程 | 审慎、领域驱动 | 数据驱动、适度 |
| 集成 | 可选 | 鼓励（多模型对比） |
| 输出 | 论文 + 复现代码 | 论文 + 代码 + 答案速查表 |
| 迭代速度 | 慢、深 | **快、有限轮次（比赛时限）** |
| 协作方式 | 端到端一次性 | **逐环节推进（plan→auto→自检→停止，逐环节等指令）** |
| 交付物 | 期刊论文 | **完整论文 + 支撑材料** |
| 评委阅读时间 | 数小时 | **5-10 分钟/篇** |
| 摘要重要性 | 高 | **极高（评委第一印象）** |

> **skill 双副本防漂移**：`math-modeling-writing` 在磁盘上有**两份独立物理副本**——
> 用户级 `~/.claude/skills/`（副本 A）与本仓库 `.claude/skills/`（副本 B，2026-09-20 由父层迁入）。
>
> **实测（2026-09-17）**：从本工作目录调用 Skill 工具，`math-modeling-writing` **解析到副本 A**
> （`~/.claude/skills/...`），并非当时位于父层的副本 B。不要假定某一份必然生效。
> **迁入后 B 成为标准的项目级位置，解析可能翻转为 B**——未复测。
>
> **因此的硬要求**：改 skill 内容后必须**两份都改并比对 md5**，只改一份会在另一个解析路径下静默失效。
> 脚本 `scripts/build_appendix.py` 等仓库内路径不受此影响（它们不走 skill 解析）。
