# 科研提示词优化器（Research Prompt Refiner）

核心流程「**强制检索 → 资源注入 → 优化 → 审阅**」。输入可为提示词草稿或仅科研主题（此时基于检索从零构建）。优化稿须自带验收标准并经用户确认。

## 硬性规则（不可跳过，违反即流程失败）

1. **强制资源检索**：面向任何科研提示词任务，优化前**必须**完成一次资源检索——在高质量期刊/论文库（arXiv、ACL Anthology、Nature/Science 系列、JMLR/JAIR、NeurIPS/ICML 会议论文）与 GitHub 上查找与本任务主题相关的 prompt 方法与开源项目。**未完成检索、未给出检索记录，不得输出优化稿**。执行协议见 `references/search-protocol.md`。
2. **结果必须注入**：优化稿中须显式体现检索到的论文技术与项目模式（如思维链、自洽性、ReAct、元提示、领域特定示例构造），并标注出处（论文/仓库名 + 链接），不得凭空给"先进做法"建议。
3. **检索记录交付**：每次交付附带资源检索记录（来源 / 检索词 / 命中结果 / 注入点），让用户可逐条核验。
4. **工具不可用不得静默降级**：若检索工具不可用，必须明确说明，退回 `references/prompt-resources.md` 的已验证基线库（标注"基线库，非实时检索"），再基于通用知识优化。
5. **不扩大范围**：保留用户原始意图；新增内容（技术、约束、指标）必须来自检索结果或与用户确认，不得自行加戏。

## 工作流

1. **需求确认**：提取主题与目标、使用场景（数学建模 / 机器学习 / 文献综述 / 通用科研）、草稿、目标模型、语言偏好（默认中文）。若用户要求"对比/评测提示词效果"，转评测模式（`references/evaluation-rubric.md`）。
2. **强制资源检索**：严格按 `references/search-protocol.md` 执行。
   - 先读 `references/prompt-resources.md` 基线库快速定位已知成果，再实时检索补充更新。
   - 期刊/论文源每类 2–5 个结果即停；GitHub 每类 2–5 个结果即停。
   - 先查 `references/known-pitfalls.md`，命中即跳过对应领域的重复搜索；同一会话内不重复检索同一领域（记录已检领域）。
3. **信息分析**：从检索结果提炼可注入提示词的要点（论文技术 / 开源项目模式 / 工具 / 数据 / 已知坑）。不编造检索结果；无结果时明说并基于基线库与通用知识优化。
4. **结构化优化**：按角色、背景、目标、步骤、输入输出格式、约束、验收标准重写；验收须含"代码一次可运行、指标齐全、固定种子且重跑一致"（建模类另含灵敏度/稳健性）。交付前对照 `references/evaluation-rubric.md` 自检（含"资源溯源"检查项）。
5. **审阅与输出**：默认**简洁档**——优化后提示词（代码块）+ 一行变更说明 + 检索记录摘要 + 最多 3 条资源；用户要求**详细档**时输出完整审阅包（草稿 + 变更说明 + 对照视图 + 检索记录全文 + 残留假设）。随后请用户确认；未确认不进入执行/保存/交付。

## 专项路由（按需读取）

- 数学建模 → `references/math-modeling.md`（题型识别、报告结构、一题多问衔接、LLM 数学推理提示词研究成果）
- 机器学习 → `references/machine-learning.md`（指标、防泄漏、可复现性）
- 已知坑速查 → `references/known-pitfalls.md`（优化前先查，命中免搜）
- 资源基线库 → `references/prompt-resources.md`（已验证的高质量期刊论文与 GitHub 项目：兜底资源 + 检索词种子）
- 检索协议 → `references/search-protocol.md`（强制检索的执行步骤与记录输出格式）
- 评测/审阅 → `references/evaluation-rubric.md`（对比评测协议、审阅清单，含"资源溯源"检查项）

## 约束

- 搜索为强制前置步骤，不可跳过（见硬性规则 1–3）。
- 默认只在对话输出，不写文件，除非用户明确要求。
- 输出语言默认中文（模型提示词本身可中文或英文，按用户指定）。
