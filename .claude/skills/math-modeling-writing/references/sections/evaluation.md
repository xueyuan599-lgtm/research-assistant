# 模型评价章节模块

## 功能

文末独立章节，系统评价模型的优点与缺点：优点说充分、缺点不回避、优点数量多于缺点。灵敏度分析、稳健性、鲁棒性等检验内容不在此章节，统一放在模型建立与求解的各问内部。

## 输入依赖

- 各问模型的建模与求解设计（编码思想、约束处理、数据防护、计算效率等核心机制）
- 各问结果与检验结论（用于佐证优点，不展开检验细节）
- 模型假设与限制（用于缺点）

## 输出骨架

```markdown
# 模型评价

## 模型的优点

1. 定性概括：具体机制或理由。
2. ……
3. ……

## 模型的缺点

1. 定性概括：具体局限或理由。
2. ……

（可选推广句）本文方法可直接推广至……场景。
```

## 写作规则

- 只写模型的优点与缺点两小节；不写灵敏度、稳健性、鲁棒性等检验内容。
- 模型评价为文末评价章，其后直接进入参考文献，不设独立结论章；各问结论已包含在模型建立与求解的每问小结中。
- 每条优缺点 = 一句话定性 + 具体机制或理由；优点呼应本问核心建模设计。
- 缺点诚实具体：贪心修复局限、计算开销、假设限制、扩展性等。
- 优点数量多于缺点，通常优点 3~5 条、缺点 2~4 条。
- 推广句可选，置于缺点之后，用“本文方法可直接推广至……场景”。
- 语言客观克制；无多余小括号；反 AI。

## 常见句式

- “模型的优点主要体现在以下方面：”
- “其一，……；其二，……。”
- “模型仍存在以下不足：”
- “本文方法可直接推广至……场景，为……提供参考。”

## 自检清单（强制最后一步）

1. 结构：仅“模型的优点”“模型的缺点”两小节。
2. 无越界：未包含灵敏度、稳健性、鲁棒性等检验内容。
3. 优点数量多于缺点。
4. 每条有具体机制或理由，不空喊。
5. 缺点诚实，不回避。
6. 无多余小括号。
7. 反 AI。
