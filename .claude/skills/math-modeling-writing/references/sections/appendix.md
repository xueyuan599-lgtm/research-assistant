# 附录章节模块

## 功能

归档正文放不下的内容：核心程序代码、运行日志、详细推导过程、繁杂图表。

## 输入依赖

- Python 代码目录或代码文件
- 运行结果文件（日志、输出表、补充图）
- 正文中需要补充的推导或图表

## 输出骨架

```markdown
# 附录

## 附录A 程序代码

> 全量源码见支撑材料 `code/src/`；下表为文件索引，关键片段见 A.1–A.n。

| 文件 | 作用 | 运行入口 |
|------|------|---------|
| `src/problem1.py` | 问题一建模与求解 | `python main.py --q1` |
| … | … | … |

## 附录A.1 关键片段

（仅贴无法从索引看出的核心算法，每段 ≤ 30 行，前后各一句说明）

## 附录B 运行结果（可选）

……
```

## 写作规则

- 附录放在论文末尾，参考文献之后。
- 只放正文放不下的内容；关键结果必须留在正文，不放进附录。
- 正文须引用附录，用“详见附录A”等表述。
- **源码不由 writer 手写**：全量代码用 `research-assistant/scripts/build_appendix.py` 扫描 `code/src/*.py` 一次性拼接生成。
  writer 只写**文件索引表 + 关键片段**，不整体重列源码。
  （动机：2026 C 题附录内联 20 个模块共 7,058 行，并被反复重建 6 次。）
- 代码片段要可读：删除无关输出与调试内容，保留核心函数与必要注释。

## 自检清单（强制最后一步）

1. 正文有对附录的引用。
2. 关键结果未藏在附录中。
3. 附录源码由 `build_appendix.py` 生成，未由 writer 整体重列。
4. 文件索引表齐全（路径 / 作用 / 运行入口三列）。
5. 反 AI。
