# 摘要章节模块

## 功能

从题目、模型与数值结果中提炼全篇亮点，生成国赛风格摘要草稿：无图、无表、无代码，篇幅 3/4~1 页。

## 输入依赖

- 题目文本（含各问要求）
- 各问的模型与方法概述（来自建模过程或代码）
- 运行结果中的核心数值指标
- 可选：亮点/特色描述

## 输出骨架

```markdown
摘要

[开头段 2~3 句] 背景 + 本文针对……问题，建立了……模型/方法。

[中间段] 按问题链展开：针对问题一，……；针对问题二，……；每问 = 模型 + 方法 + 核心数值。

[收尾段 可选] 提供了一种……方法 / 可为……提供参考。

关键词：……（4~6 个）
```

## 写作规则

- 逐问对应：题目几个问，摘要就有几句或几段，不漏问、不改顺序。
- 数值是硬通货：优化/预测/物理类题目必须写清核心数值结果；数字与运行结果文件一致。
- 一句一功能：每句话只讲问题、方法或结果之一，不堆叠概念。
- 术语括号最多一次：缩写（如 LMM）只在首次出现时括注，后续直呼其名。
- 数字只留核心：删掉过程性数字（预处理样本数、迭代次数、网络参数）。
- 措辞克制：用“异常数据、数据错误、一致性校验”等中性词；不用“污染数据、从源头阻断、技术范式、完整可复现”等营销化表达。
- 创新点表述克制：用“提供了一种有效方法”“为……提供参考”“具有一定应用价值”。
- 客观陈述：用“结果表明/求得/验证了/最终得到”，不用“我认为/大概”。

## 常见句式

- 开头：“针对……问题，本文建立了……模型”“本文基于……数据，构建了……”
- 中间：“针对问题一，考虑……，建立……模型，利用……方法求解，得到……”“结果表明……”
- 结尾：“提供了一种有效方法”“可为……提供参考”“具有一定应用价值”
- 关键词：从“问题、模型、方法”三类中取 4~6 个词。

## 反 AI 自检（强制最后一步）

成稿后逐条检查，任一不通过必须重写对应语句：

1. 括号审查：缩写括号全篇不超过 1 次；无“概念＋缩写＋解释＋数字”连排。
2. 一句一功能：无“构建了……融合……协同……”式长句。
3. 措辞审查：无“污染数据/从源头阻断/技术范式/完整可复现”等营销化词。
4. 问题链：存在“针对问题一/二/三……”或“首先……其次……最后……”；单问题目按“问题→方法→结果”的建模流程顺序展开亦可。
5. 数字取舍：只保留结果性核心指标，过程性数字已删除。
6. 创新点表述：未夸大包装。
7. 通读：朗读一遍无 AI 腔（连续括号、并列概念、过度修饰）。
8. 数值核对：摘要中每个数字与运行结果文件一致。
