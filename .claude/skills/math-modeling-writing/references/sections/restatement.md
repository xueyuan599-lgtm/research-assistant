# 问题重述章节模块

## 功能

用自己的话重组赛题背景与问题，形成“问题背景 + 问题提出”两小节，不照抄原题，为问题分析做铺垫。

## 输入依赖

- 赛题原文（题目背景、问题一~N 的完整表述）
- 可选：相关文献/背景资料（用于客观化痛点）

## 输出骨架

```markdown
# 问题重述

## 1.1 问题背景

[漏斗式四层：宏观背景 → 技术/对象介绍 → 现实痛点与矛盾 → 研究必要性]
（痛点可用文献数据客观化；最后一句点出“亟待解决的关键科学问题”）

## 1.2 问题提出

[过渡句：为使……，现需结合实际情况与所给数据建立数学模型，分析以下问题：]

问题一：……（重组语言，保留关键约束）
问题二：……

## 1.3 我们的工作（可选，C023 格式）

[总览一段：各问将如何解决的整体思路]

[图占位：总体流程图]
```

## 写作规则

- 不照抄原题，逐问用自己的话重述（查重要求）。
- 背景与问题分开两个小节。
- 背景按漏斗展开：宏观 → 具体技术/对象 → 痛点矛盾 → 必要性；痛点要有事实或数据支撑，不空喊。
- 问题部分每题一段，保留题目中的关键约束（如“并检验其显著性”“并分析误差的影响”）。
- 只做“重述”，不提前出现模型选择、求解方法或结果（那是问题分析与求解的内容）。
- 可选收尾 1.3 我们的工作：总览各问的整体解决框架并配总体流程图（C023 格式）；只列框架，不重复 1.2 细节。
- 语言客观克制，避免营销化措辞。

## 常见句式

- 背景开头：“随着……的发展，……已成为……”；“……是……的关键环节”。
- 痛点：“然而，……面临……的矛盾：过早……，过晚……”；“此外，……仍有待提升”。
- 必要性：“因此，……已成为……亟待解决的关键科学问题”。
- 过渡：“为使……获得更好的……，现需结合实际情况与所给信息建立数学模型，分析以下问题：”。
- 问题句：“问题一：分析……，给出……，并检验……”。
- 总览：“针对以上问题，本文的整体工作框架如下……”。

## 自检清单（强制最后一步）

1. 查重：无照抄原题的句子。
2. 结构：1.1 问题背景 + 1.2 问题提出齐全。
3. 漏斗完整：宏观 → 技术/对象 → 痛点 → 必要性四层齐全。
4. 逐问覆盖：问题数量与顺序和赛题一致，不漏问。
5. 无越界：未提前出现模型、方法或结果。
6. 1.3 可选：如使用，只列整体框架并配图占位，不重复问题细节。
7. 反 AI 检查：无括号堆叠、无概念堆叠、无“污染/范式/赋能”等营销化措辞。
8. 痛点有支撑：背景中的问题描述有事实、数据或文献支撑（可用可不用文献，但不能空喊）。
