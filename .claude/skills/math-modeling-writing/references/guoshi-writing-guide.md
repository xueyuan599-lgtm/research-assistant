# 国赛数学建模写作指南

> 整合自：国赛写作模板要点指导 + Word排版规范 + AI提示词框架
> 适用：全国大学生数学建模竞赛（国赛），也可参考用于研赛/电工杯等国内赛事

---

## 一、论文标准结构

```
1. 论文标题
2. 摘要 + 关键词
3. 问题重述
4. 问题分析
5. 模型假设
6. 符号说明
7. 模型的建立与求解
   ├── 问题一：模型建立 → 求解 → 结果
   ├── 问题二：模型建立 → 求解 → 结果
   └── 问题三：模型建立 → 求解 → 结果
8. 模型分析与评价
9. 结论
10. 参考文献
11. 附录（代码）
```

> ⚠️ **实现注记（C023 设计）**：本技能按 `SKILL.md` 章节路由表实现——「问题分析」不单独成章，嵌入每个问题的建立与求解开头（1~2 段）；「结论」并入每问小结，不设独立章节。故本节结构中的独立「问题分析 §4」与「结论 §9」已被取代，编辑章节时以 `references/sections/` 各模块为准，勿改回独立章节。

## 二、各模块详细规范

### 1. 论文标题

**格式**：`基于XXX模型/算法的XXX问题研究`

- 黑体不加粗 三号 居中
- 体现核心方法和研究对象

### 2. 摘要（重中之重！）

评阅老师每篇只看约15分钟，摘要决定了第一印象。

**结构：**
```
开头段（2~3句）：背景 + 采用了什么方法 + 解决了什么问题
中间段：针对每个问题分别叙述（模型 + 方法 + 结果，必须写清数值）
总结段（可选）：论文亮点、推广意义
关键词（4~6个）
```

**规则：**
- 文字简练、陈述客观
- ❌ 不加图、不加表格
- ❌ 不写详细的求解过程
- 控制在 3/4 页 ~ 1 页
- 优化/预测/物理类题目必须写清数值结果
- 建议/评价类题目必须写清结论和数据依据

**通用模板：**
```
开头：
本文主要研究了XXX问题。根据XXX特征，利用XXX模型/方法，求解出XXX。

针对问题一，考虑XXX，建立XXX模型，利用XXX方法求解出XXX（明确数值）。
针对问题二，考虑XXX，建立XXX模型，利用XXX方法求解出XXX（明确数值）。
针对问题三，考虑XXX，建立XXX模型，利用XXX方法求解出XXX（明确数值）。

总结：本文的特色在于XXX（亮点），为XXX提供了参考依据。
关键词：模型1  模型2  方法1  方法2
```

### 3. 问题重述

- 用自己的语言重新组织，**不可直接复制粘贴原题**（查重！）
- 包含问题背景 + 问题的整理（问题一、问题二、问题三）
- 可查阅文献丰富背景

### 4. 问题分析

**这是将具体问题抽象为数学模型的桥梁**，体现对问题的认识深度。

- 每个问题单独分析一段
- 分析过程简明扼要，不放结论
- 可用流程图展示分析思路
- 放在问题重述后面作为单独一节（最常见）

### 5. 模型假设

常见假设来源（按优先级）：
1. **题目明确给出的** — 直接搬过来
2. **排除小概率事件** — 交通事故、经济危机、设备故障等
3. **只考虑核心因素** — 忽略次要因素
4. **模型自带假设** — 理性人假设、无后效性、正态分布等
5. **参数形式假设** — Logistic增长、指数分布、泊松分布等
6. **简化模型的假设** — 与题目紧密结合的自定义假设

要求：以严格确切的语言表达，假设要与结果有因果关系。

### 6. 符号说明

**三线表格式：**

| 符号 | 含义 | 单位 |
|------|------|------|
| \( x_i \) | 第 i 个决策变量 | 万元 |

- 不需要放所有变量，临时变量可以不放
- 下文首次出现也要解释
- 与数学习惯相符，不用程序变量名

### 7. 模型的建立与求解

**模型建立：**
- ③ 一定要有分析，且分析在模型前面
- ③ 一定要有明确的模型表达式
- ③ 关系式明确，思路清晰易读

**模型求解：**
- ③ 建模与求解截然分开
- ③ 不能以程序代替求解过程
- ③ 必须有必要的求解步骤（最好像算法一样分步写）
- ③ 结果要全，所有问题都必须有详细结果和中间结果
- ③ 非常明显的结果也要明确写出来
- 结果放在对应位置，尽量不放在附录

### 8. 模型分析与评价

**灵敏度分析**：控制变量法，改变一个关键参数，观察结果变化

**误差分析**：预测问题/数值计算类问题必须做

**结果检验**：使用模型前的检验（一致性检验、准指数规律检验）+ 使用后的检验（稳定性检验）

- 优点说充分，缺点不回避
- **优点数量要多于缺点**
- 推广：完成了什么工作？达到了什么目的？为后续提供什么思路？

### 9.结论

### 10. 参考文献

- 引用别人的成果必须在原文明确标注
- 引用格式要正确

### 11. 附录

包括：详细证明过程、大流程图、源程序、繁杂图表等

## 三、排版规范（Word版）

### 字号字体

| 层级 | 字体 | 字号 | 对齐 |
|------|------|------|------|
| 论文题目 | 黑体不加粗 | 三号 | 居中 |
| 摘要标题 | 黑体不加粗 | 四号 | 居中 |
| 摘要正文 | 宋体 | 小四 | 首行缩进2字符 |
| 一级标题 | 黑体不加粗 | 四号 | 居中 |
| 二级标题 | 黑体不加粗 | 小四 | 居左 |
| 三级标题 | 黑体不加粗 | 小四 | 居左 |
| 正文 | 宋体 | 小四 | 首行缩进2字符 |
| 英文正文 | Times New Roman | 小四 | 首行缩进2字符 |
| 图注表注 | 宋体/Times加粗 | 五号 | 居中 |

### 其他规范

- **表格**：三线表（上下线1.5磅，表头下线1.0磅）
- **公式**：居中 + 右侧编号（用Mathtype或Word自带编辑器，不能截图）
- **图注**：段前0段后0.5行
- **表注**：段前0.5段后0行
- **各级标题**：前后各0.5行
- **页码**：从正文开始

## 四、排版规范（LaTeX版）

### 1. 表格规范

**表格选型原则**
- 简单数据表（实验结果、参数敏感性、误差比较、模型评价指标）→ 用 `tabular`，列全部居中 `c`，表格自动收缩到内容宽度，**不要**用 `tabularx{\textwidth}` 撑满整行
- 复杂文字表（符号说明、中英变量对照、含长描述的对照表）→ 用 `tabularx{\textwidth}`，短列用 `c` 居中、长描述列用 `X` 自动换行
- 表头统一居中加粗：`\multicolumn{1}{c}{\textbf{表头}}`
- 字号优先 `\footnotesize` 或 `\small`；`\tabcolsep` 默认即 6pt，无需加大
- 表格位置使用 `[!htbp]`，不要用 `[H]` 强制固定位置导致页面大片留白

**简单数据表：tabular + 列全居中**

```latex
\begin{table}[!htbp]
\centering
\caption{您的表标题}
\footnotesize
\begin{tabular}{c c c}   % 列全部居中，列数按需增减 c
\toprule
\multicolumn{1}{c}{\textbf{列1}} & \multicolumn{1}{c}{\textbf{列2}} & \multicolumn{1}{c}{\textbf{列3}} \\
\midrule
内容1-1 & 内容1-2 & 内容1-3 \\
内容2-1 & 内容2-2 & 内容2-3 \\
\bottomrule
\end{tabular}
\end{table}
```

**复杂文字表：tabularx + 短列居中 + 长列自动换行**

```latex
\usepackage{tabularx}   % 在导言区添加

\begin{table}[!htbp]
\centering
\caption{您的表标题}
\footnotesize
\begin{tabularx}{\textwidth}{c c X}   % 前两列居中，最后一列 X 自动换行
\toprule
\multicolumn{1}{c}{\textbf{列1}} & \multicolumn{1}{c}{\textbf{列2}} & \multicolumn{1}{c}{\textbf{列3}} \\
\midrule
内容1-1 & 内容1-2 & 内容1-3（较长文本可自动换行） \\
内容2-1 & 内容2-2 & 内容2-3 \\
\bottomrule
\end{tabularx}
\end{table}
```

**注意事项**
- ❌ 简单表不要用 `tabularx{\textwidth}`：两列短内容会被强制拉伸到整行宽，中间留巨大横向空白，浪费约三成版面
- 表头若过长，用 `\thead{}`（需 makecell 包）或缩写，并在脚注中说明
- 表格标题与正文之间留空一行（LaTeX 自动处理）
- ⚠️ **超长无断点字符串**（长英文单词、长数字串、URL、公式命令）无法在中间断行，会顶破列宽溢出。中文可逐字断行，无此问题；`l`/`r` 列完全不换行，长内容必须放 X 列

**防溢出写法**

```latex
% X 列加 \raggedright，避免两端对齐产生难堪的空白
\begin{tabularx}{\textwidth}{c>{\raggedright\arraybackslash}X
                                >{\raggedright\arraybackslash}Xc}

% 单元格内防溢出（三选一，按情况用）
\seqsplit{0.8473125}                % 长数字串，可任意断行（需 \usepackage{seqsplit}）
\url{https://www.example.com/...}   % URL 自动断行（需 \usepackage{url}）
P_{\text{load}}(t)\allowbreak       % 公式中手动插入断点
```

### 2. 列举项（item）规范

**原则**
- 用于列举若干要点、步骤、假设、结果等
- 使用 enumerate 环境获得自动数字编号
- 不使用 `\item[...]` 自定义标签（避免长标签溢出）
- 不加粗条目标题（如需强调，可在文中用斜体或单独成段）
- 标题直接写在 `\item` 的内容开头，后跟冒号，接着正文

**推荐写法**

```latex
\begin{enumerate}
  \item 第一点标题：这里是详细说明，文字可长可短，自动换行。
  \item 第二点标题：同样格式，保持统一。
  \item 第三点标题：若内容较长，会自然换行，不会溢出。
\end{enumerate}
```

**特殊情况**

如果某个条目标题特别长（超过10个汉字）且正文也很长，建议改用独立段落形式（空行分隔），手动编号，避免列表环境导致缩进不自然。独立段落示例：

```latex
\textbf{1. 很长的标题（可选加粗）} 这里写详细内容，段落自动换行。

\textbf{2. 另一个长标题} 内容继续。
```

若坚持不加粗，可省略 `\textbf{}`，直接用数字+点号开头。

### 3. 整体模板设置建议（导言区）

为减少重复代码，可在导言区做如下设置：

```latex
% 表格相关
\usepackage{tabularx}
\usepackage{booktabs}   % 提供\toprule等

% 列表相关（全局设置）
\usepackage{enumitem}
\setlist[enumerate]{leftmargin=*, label=\arabic*., itemsep=2pt, parsep=0pt}   % 自定义编号样式和间距
```

这样所有 enumerate 环境默认就是 1. 2. 3. 格式，且缩进统一，无需每次设置。
