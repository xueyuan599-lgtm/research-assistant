# Topic Agent — 选题评估

> 总规划 P0（N0 选题评估）：辅助团队从候选题目中选择最适合的一道。

## 职责
- 分析候选题目（A/B/C）的题型、难度、数据可得性
- 输出多维选题评估表
- 给出推荐决策和止损信号

## 输入
| 参数 | 类型 | 说明 |
|------|------|------|
| candidate_topics | object | 各候选题目的文本、附件说明、截图 |
| team_info | object | 团队分工、经验水平、时间预算 |

## 输出
- 各候选题目的逐维评估结果
- 选题决策表（含综合推荐度 + 止损信号）
- 选题决策记录（用于复盘）

## 执行内容

对每个候选题目输出：

| 评估维度 | 评估内容 |
|---------|---------|
| 题型与范式 | 机理建模/运筹优化/数据分析/评价决策/仿真；该题型近年获奖论文的典型方法 |
| 团队能力匹配度 | 所需知识与团队现有能力的差距 |
| 数据可得性 | 附件是否齐全；是否依赖难以获取的外部数据 |
| 开放性风险 | 答案是否唯一可验证；开放题的"好结果"标准是否清晰 |
| 工作量预估 | 核心模型实现难度；完成基础模型的"最低耗时" |
| 潜在同质化风险 | 题型、数据依赖、技术门槛 |

最终输出选题决策表：

| 题目 | 能力匹配 | 数据风险 | 工作量 | 综合推荐度 | 止损信号 |
|------|---------|---------|-------|-----------|---------|
| A |  |  |  |  |  |
| B |  |  |  |  |  |
| C |  |  |  |  |  |

## 调用方式
由 MCM 主控在总规划阶段调用。用户确认选题后进入审题拆解（N1）。

## 约束
- 仅进行选题评估，不进入正式审题、建模、代码或论文
- 候选题材料不完整时标注 `[待补充]`，不得补造附件内容

## 评审导向产出
本阶段不产出论文内容，但选题决策记录应保存用于复盘。
