# CUMCM 论文结构模板（对齐 math-modeling-writing skill）

> 全国大学生数学建模竞赛论文结构，章节组织遵循 `math-modeling-writing` skill
> 的 `references/sections/*.md` 模块（问题分析嵌入各问、检验并入各问稳健性、不设独立结论章、模型评价只写优缺点）。
>
> **协作方式**：各节**独立成文件** `paper/sections/{序号}-{章节}.md`，由环节循环逐节产出；
> 全部完成后一次性合并成论文。文件序号 = 论文最终顺序（合并用），与环节执行顺序（建模在前、摘要最后）不同。

## 总体要求

- **正文不超过 30 页**（官方硬约束）。完整口径（起始页、目录、摘要页、附录）以
  `.claude/rules/04-mcm-track.md` §强制规则6 为**唯一出处**，依据《全国大学生数学建模竞赛论文格式规范》(2026) 第三、四条
- 使用正式中文撰写
- 图表规范：图下表上、三线表、编号连续
- 公式编号：(1)(2)(3) 连续
- 首次符号必须定义
- 匿名：不得出现学校、队员、导师信息
- 每节写作加载对应 skill 章节模块，执行其**自检清单**为最后一步

## 章节结构与文件序号

> 本表只定义**文件槽位 ↔ 内容要点**。环节、章节模块、输入依赖、对应 agent 的对应关系
> 见 `.claude/rules/04-mcm-track.md` §环节清单（**唯一出处**），此处不重复。

| 文件 | 内容要点 |
|------|---------|
| `00-摘要.md` | 问题→方法→关键结果→检验→结论；必须含可检验数值；强制反 AI 自检 |
| `01-问题重述.md` | 问题背景 + 问题要求，复述不抄题 |
| `02-模型假设.md` | 4-8 条核心假设，每条须在模型中实际使用 |
| `03-符号说明.md` | 符号表，从已写模型节提取，全稿一致 |
| `04~08-问题N-建模与求解.md` | 含问题分析段、建模、求解、结果、稳健性、小结 |
| `09-模型评价.md` | 只写优缺点（至少一项实质局限），不写"改进方向"空谈 |
| `10-参考文献.md` | 仅列正文实际引用，GB/T 7714 格式 |
| `11-附录.md` | 代码清单（可选）、关键数据表 |

> 文件序号为固定槽位：建模求解章用 04~08 容纳 3-5 问（问数不足时留空，超过时顺延递增）；
> 模型评价/参考文献/附录固定 09/10/11。合并按文件名排序即可得到论文正确顺序。

## 逐问章节（模型建立与求解）内部结构

> **本节是 skill `math-modeling-writing/references/sections/model-solve.md` 的本地镜像**，
> 供沙箱内快速查阅（如 `diagnosis-agent.md` 按 N.1~N.6 派活）。**有冲突时以 skill 模块为准**，
> 不在此处独立演进。

按 `model-solve.md` 模块模板，每问一节、自定义三级标题：

```text
问题N 模型的建立与求解
├─ N.1 问题分析（嵌入本问开头：该问核心、难点、思路）   ← 来自 restatement/analysis 模块思路
├─ N.2 模型的建立（假设→符号→公式推导，含图/表）
├─ N.3 模型的求解（求解方法、算法、实现）
├─ N.4 结果与分析（关键数值、图表、与基准对比——仅关键小问展示）
├─ N.5 稳健性分析（该问适配检验 + 灵敏度，非全题一套）
└─ N.6 小结（该问结论，一句话）
```

## 合并约定（终稿）

1. 环节循环完成后，按文件名排序拼接 `paper/sections/*.md` → `paper/论文草稿.md`
2. 摘要置前单独一页；检查全稿编号连续（章节/图表/公式）
3. 补**答案速查表**（表头与规则见 `agents/mcm/writer-agent.md` §答案速查表，**唯一出处**）
4. critic 评审自查表（N7 唯一触发）→ 团队核验 → `paper_final.md`
5. （可选）用 skill 内置 md2word 转 Word + 无损校验

## 与旧结构的差异（评审导向）

| 旧结构 | 新结构（skill 对齐） |
|--------|---------------------|
| 独立"问题分析"章 | 嵌入各问"问题分析"段 |
| 独立"模型检验"章 | 并入各问"稳健性分析" |
| 独立"结论与建议"章 | 各问小结 + 摘要总结 |
| 模型评价含"改进方向" | 只写优缺点（至少一项实质局限） |
