# MCM 关键节点检查清单

> 国赛流水线的节点检查清单，供**团队逐项核验**。
> 节点检查由团队把关，AI 不替团队做决定。critic 仅终稿（N7）执行评审自查表。
>
> **协作模式**：总规划（N0~N3 前置一次性）→ 环节循环（逐环节 S 自检）→ 终稿合并（N7）。
> 不再有全题的 N4/N5/N6 独立检查节点——模型推导、代码、诊断都按环节逐问进行，随环节自检 S 核验。

## 检查流程

```
主控产出节点/环节内容
  → 团队按下方清单逐项核验（每项标 ✅/❌）
  → 记录节点/环节状态到 outputs/mcm_{题目}/checkpoints/节点状态记录.md
  → 全部通过 + 团队确认 → PASS → 进入下一节点/环节
  → 有未通过项 → FAIL + 退回对象 → 退回对应 Agent 修复后重新核验
```

## 前置节点（总规划 · 一次性）

## N0 选题评估（总规划 P0 / topic-agent）

**关键产出**：选题决策表 + 推荐决策

| # | 检查项 | 核验方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 决策表 6 维度完整 | 对照 topic-agent 输出的评估表 | 题型/能力/数据/开放性/工作量/同质化 6 项均有内容 |
| 2 | 止损信号明确 | 看决策表"止损信号"列 | 每道候选题都有清晰止损条件（何时放弃该题） |
| 3 | 所选题目团队能力匹配 | 团队自评 | 编程手能实现核心算法，时间预算够 |

**通过** → 团队确认题目 → 记录 PASS → 进入 N1（题目已定可跳过）

---

## N1 审题拆解（总规划 P1 / planner-agent）

**关键产出**：拆解表 + 题型分类 + Mermaid 逻辑图 + 风险清单 + 待补充清单

| # | 检查项 | 核验方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 每小问直接/隐含目标清楚 | 对照题目原文逐问核对 | 所有小问（含隐含要求）都被列出，无遗漏 |
| 2 | 题型分类正确 | 团队判断题型 | 优化/预测/评价/机理等分类与题目要求一致 |
| 3 | 小问依赖关系明确 | 看 Mermaid 逻辑图 | 数据流、参数依赖、输出整合关系画清楚 |
| 4 | 风险/待补充清单覆盖 | 对照附件说明 | 字段歧义/缺失、单位尺度、约束冲突均已列出 |

**通过** → 团队确认理解无误 → 记录 PASS → 进入 N2

---

## N2 模型方案（总规划 P1 / planner-agent）

**关键产出**：模型方案表（A/B 方案）+ 关键小问标注 + 每小问图表方案 + 摘要初稿 + **环节清单 + 论文骨架**

| # | 检查项 | 核验方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 每问 A/B 方案齐全 | 对照模型方案表 | 每个小问都有基础方案 A + 改进方案 B，且 B 说明改进点 |
| 2 | 关键小问已标注 | 看"关键小问?"列 | 全题只标 1-2 个关键小问（分值高/创新点） |
| 3 | 每问图表方案合理 | 对照 §4.2 图表方案表 | 图型与该问数据特征匹配，定制点明确 |
| 4 | **环节清单 + 论文骨架齐全** | 对照 planner §7 输出契约 | 按 skill 章节模块列出环节顺序、每环节输入依赖与对应 agent；编号框架给出 |
| 5 | 摘要初稿过 30 秒测试 | 团队阅读 | 外行人 30 秒能说出问题/方法/结果/结论 |

**通过** → 团队确认模型路线 + 环节清单 → 记录 PASS → 进入 N3（可并行）

---

## N3 数据审查（总规划 P2 / data-agent）

**关键产出**：数据字典 + 数据质量检查表 + 清洗规则

| # | 检查项 | 核验方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 字段以实际附件为准 | 打开附件核对 | 字段名/类型/单位/缺失与真实文件一致，无编造 |
| 2 | 缺失/异常/泄漏已查 | 看质量检查表 | 重复/缺失/异常/泄漏 4 类都给出检查方法与处理 |
| 3 | 清洗规则明确可执行 | 团队判断 | 处理缺失/异常的具体方法可照做，参数可复现 |

**通过** → 团队确认数据方案 → 记录 PASS → 进入环节循环（可并行）

## 环节自检 S（环节循环 · 每环节完成后）

**范围**：`.claude/rules/04-mcm-track.md` §环节清单 所列全部环节（**唯一出处**，此处不复述清单）。
**对建模环节**（逐问建模与求解）：自检覆盖该问的 model-builder → coder → diagnosis → writer 整条链路。
**判定者**：团队（写作自检清单由 writer 先自查，团队再核验）。

**关键产出**：`paper/sections/{序号}-{章节}.md` + 该问代码/结果（建模环节）+ 自检清单结果

**层级归属**：第 1/2/3/5 项为 L1（必做）；第 4 项为 L2（按需）；第 6/7 项为轻量自检；第 8 项为**机械前置**（闸门只给退出码，见 `.claude/rules/06-cost-discipline.md`「轮次闸门」）。
L1/L2/L3 的定义、默认与触发条件以 `.claude/rules/06-cost-discipline.md` 为**唯一出处**（本文件不重复其条文）。

| # | 检查项 | 核验方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | **该节自检清单逐项过** | 对照 skill 章节模块的"自检清单" | 该节对应 `math-modeling-writing` 模块的自检项全部 ✅（writer 先自查，团队复核） |
| 2 | 建模环节：代码物理运行无错 | 运行该问 problemN.py | 无报错、结果文件生成（物理验证协议），未运行处已标 `[待运行]` |
| 3 | 建模环节：数值真实与运行结果一致 | 抽查关键数值 vs 运行输出 | 论文内数值与 `outputs/` 实际结果一致，无编造 |
| 4 | 建模环节：该问适配检验已做 | 对照 `agents/mcm/diagnosis-agent.md` 第 2 步的该问检验计划表 | 该问模型类型的适配检验（预测/优化/评价/机理等）已完成，非全题一套 |
| 5 | **编号/图表衔接** | 对照论文骨架 + 已产出的 sections | 标题序号、图表/公式编号与已有草稿连续，无重复/跳号 |
| 6 | 该节信息密度 | 读该节正文 | 每段含具体数字/方法名/引用，无空洞表述 |
| 7 | 禁用词自检 | 按 `.claude/rules/02-academic-writing-standards.md` §1 禁用词表扫描该节 | 该表所列词全部无出现（**唯一出处**为该规则文件，此处不复述词表） |
| 8 | **轮次闸门已闭合** | 跑 `python scripts/round_gate.py check --ws <run_dir> --target S<N>` | **退出码 0** 才算通过；非 0 一律不得标 PASS（各码含义见脚本 docstring） |

**通过** → 记录 S 环节 PASS → **汇报并暂停，等待用户下一环节指令**（与 `.claude/rules/04-mcm-track.md`「逐环节推进」一致；用户显式说"连跑 N 个环节"时批量执行，执行完仍回到停点；可随时插话指定环节，part_scope 优先生效）
**不通过** → FAIL + 退回对象（writer / coder / diagnosis）→ 修复后重新核验（轮次上限见 `.claude/rules/06-cost-discipline.md`「审查轮次封顶」，**全局唯一次数口径**，不在本节点另计）

## N7 终稿合并（终稿 · writer-agent + critic-agent）

**触发**：环节循环全部完成（sections 全齐）后合并终稿，critic 在此唯一触发。

**关键产出**：合并的论文终稿 + 答案速查表 + 评审自查表

| # | 检查项 | 核验方法 | 通过标准 |
|---|--------|---------|---------|
| 1 | 所有环节 sections 已产出 | 对照环节清单 | ①~⑫ 全部有 `paper/sections/` 文件，无缺节 |
| 2 | 摘要含可检验结果 | 读摘要 | 含具体数值/方案/规律（非"取得较好效果"空泛表述） |
| 3 | 每问答案 30 秒定位 | 对照答案速查表（表头见 `agents/mcm/writer-agent.md` §答案速查表，**唯一出处**） | 逐问能在 30 秒内找到答案及论文位置 |
| 4 | critic 评审自查表全部通过 | 运行 critic（终稿唯一触发点） | 16 项自查 + 5 项写作质量全 PASS，或非关键项 FAIL 已标注 |
| 5 | 全稿禁用词扫描 | 按 `.claude/rules/02-academic-writing-standards.md` §1 扫描合并后全文 | 该表所列词全稿无出现 |
| 6 | 正文篇幅合规 | 合并后统计正文页数 | 正文 ≤30 页且无目录（完整口径见 `.claude/rules/04-mcm-track.md` §强制规则6） |
| 7 | **轮次闸门已闭合** | 跑 `python scripts/round_gate.py check --ws <run_dir> --target N7` | 退出码 0。N7 上限为 **1 轮**（脚本硬编码，不随环境变量放宽），与「critic 自收 1 轮」一致；触顶即汇总 FAIL 升级团队 |

**通过** → critic PASS + 团队确认 → 记录 PASS → **交付**

## 节点/环节状态记录模板

写入 `outputs/mcm_{题目}/checkpoints/节点状态记录.md`：

**格式约束**（见 `.claude/rules/06-cost-discipline.md`）：**只追加行，不重写全文**；单条 ≤ 200 字；
叙述性长文不得写入本文件。`tokens` 列为该环节估算消耗（归因用，一行一个数）。

```markdown
# 节点状态记录

| 节点/环节 | 产出文件 | 检查核验 | 状态 | 时间 | tokens | 退回对象 |
|----------|---------|---------|------|------|--------|---------|
| N0 选题 | outputs/.../topic.md | 3/3 通过 | PASS | 07-31 10:00 | ~12k | - |
| N1 审题 | outputs/.../planner.md | 2/4 (依赖未明确) | FAIL | 07-31 10:30 | ~31k | planner-agent |
| N2 方案 | outputs/.../planner.md | 5/5 通过 | PASS | ... | ~8k | - |
| N3 数据 | outputs/.../data_profile.md | 3/3 通过 | PASS | ... | ~22k | - |
| S① 问题重述 | paper/sections/01-问题重述.md | 自检 7/7 | PASS | ... | ~9k | - |
| S② 问题一建模求解 | paper/sections/04-问题一-建模与求解.md + src/problem1.py | 7/7 通过 | PASS | ... | ~64k | - |
| S③ 问题二建模求解 | paper/sections/05-问题二-建模与求解.md | 5/7 (编号跳号) | FAIL | ... | ~70k | writer-agent |
| S⑫ 摘要 | paper/sections/00-摘要.md | 自检 7/7 | PASS | ... | ~11k | - |
| N7 终稿 | paper/paper_final.md | 6/6 通过 | PASS | ... | ~40k | - |
```

> **FAIL 处理**：记录"退回对象"，退回对应 Agent 修复后重新核验该节点/环节；
> 修复轮次上限见 `.claude/rules/06-cost-discipline.md`「审查轮次封顶」（**全局唯一次数口径**），
> 超限即升级给团队人工介入（避免死循环），不在本文件另设计数。
